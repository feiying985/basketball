# 进球识别评估与标注工具

这个目录放**本地评估**用的工具：把人工标注的投篮事件和检测器输出对齐，计算
precision/recall、命中率、时间误差和失败清单。视频和标注不提交到仓库。

## 快速开始

```bash
cd server
python -m tools.evaluate \
  --dataset /data/basketball-eval \
  --labels /data/basketball-eval/labels.csv \
  --detector classical \
  --out reports/2026-11-11-classical
```

输出：

- `reports/.../report.json`：逐视频、逐场景指标和失败明细，便于和上一次结果对比；
- `reports/.../report.md`：可直接看的总表、分视频表、失败清单。

可选参数：

| 参数 | 说明 |
| --- | --- |
| `--detector classical\|stub` | 检测器后端，默认 `classical` |
| `--tolerance 1.0` | 检测事件与标注时间的匹配容差（秒） |
| `--hoop-roi x,y,width,height` | 本次评估统一使用的手动篮筐 ROI（归一化） |
| `--no-duration` | 不读视频时长（误报/分钟为空） |
| `--strict` | 有视频缺失或分析失败时返回非 0 |

## 标注格式

复制 `labels_template.csv`，一行一个**投篮事件**。必填列：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| `clip` | 是 | 视频文件名；相对 `--dataset` 目录，或绝对路径 |
| `shot_id` | 是 | 同一视频内从 1 开始的事件编号 |
| `rim_time` | 是 | 球心穿过筐口平面（未中时最接近筐口）的时刻，秒，±0.3s |
| `made` | 是 | 1=进球，0=未中；不要只标进球 |
| `release_time` | 否 | 出手时刻，秒；可空 |
| `occluded` | 否 | 1=过筐瞬间被手/身体/网遮挡或出画 |
| `camera` | 否 | `side` / `front` / `oblique` / `handheld` |
| `lighting` | 否 | `day` / `night` / `indoor` |
| `hoop_roi` | 否 | `x,y,width,height`（0-1 归一化）；自动找筐失败时填，同一视频保持一致 |
| `notes` | 否 | 擦筐、弹框、三不沾、传球经过等 |

示例见 `labels_example.csv`。

## 这两段视频怎么标

1. 先复制模板，给两段视频各建几行；`clip` 用实际文件名。
2. 用慢放/逐帧播放，找**每一次出手**，不要只找进球。传球、运球经过篮筐不算投篮。
3. `rim_time` 记球心穿过筐口平面（或未中时离筐口最近）的那一帧；30fps 下 1 帧约
   0.033s，±0.3s 即可。
4. `made=1` 只给球真正穿过篮网/筐口的球；擦筐、弹框、三不沾、偏出都记 `made=0`。
5. 如果过筐瞬间被遮挡，记 `occluded=1`，但仍然记录时间；完全看不清的球不要猜。
6. 如果 App 的自动找筐不准（或篮筐不是橙色），在**每一行**填同一个 `hoop_roi`；
   不知道坐标时可以先不填，跑一次评估看 `hoop_confidence`/失败原因再补。
7. `camera`、`lighting` 用于分场景统计；两段视频可以标 `handheld`/`side`、`day`。

> 当前检测器本身可能不准，不要直接把它的输出当正确答案。可以先用它跑一遍作为
> 候选，再逐帧核对、补漏和改正；这比从零找每一球省时间。

两段视频的已知情况：46s 那段是半固定机位，能看到多个进球，适合作为第一批；
7.3s 那段在横移，篮网会出画，只标画内能确认的出手，确认不了就留空。

## 评估指标

- **事件精确率/召回率**：检测事件与标注事件按时间一对一匹配，容差默认 ±1.0s；
- **命中精确率/召回率**：只统计 `made=1` 的事件，直接对应「进球片段」质量；
- **命中/未中分类准确率**：匹配上的事件里 `made` 判断正确的比例；
- **时间误差**：匹配事件的 |检测时间 − 标注时间|，报 MAE 和 p95；
- **误报/分钟**：未匹配的检测事件数 ÷ 视频总分钟数（需要读视频时长）。

## 隐私与限制

- 视频和标注可能包含人物画面，放在私有目录/OSS，不要提交到公开仓库；
- 评估工具不读取/保存视频帧，报告只含时间点和统计；
- 单段视频、小样本的指标波动很大，至少 10–15 段、30–60 个事件后再做结论；
- 合成视频单测只能验证逻辑，不能替代真实球场评估。
