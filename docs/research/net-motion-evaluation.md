# 篮网能量法评估：能否替换现有进球识别

> 评估日期：2026-11-08。对象：本地 `server` 原型（FastAPI + OpenCV，未入库）里的
> 「篮网 ROI 帧间差分 + 局部基线尖峰」检测器。
>
> **结论：不整体替换现有识别流程。** 它只在「固定机位 + 篮网清晰」的场景下能作为
> 可选的「命中片段」检测器/命中确认信号；它的时序后处理值得借鉴。整体升级路线仍以
> [进球识别精度提升方案](https://github.com/feiying985/basketball/pull/13) 为准。

## 1. 背景

App 当前链路是：手机拍摄/选择视频 → 上传服务端 → 检测投篮事件（`made=true/false`）
→ App 展示命中/未中与命中率，并为命中球生成片段。当前服务端是经典 CV 基线
（HSV 橙色找球、持续橙色区域找筐、贪心跟踪、2D 穿筐几何），颜色、机位和遮挡假设较强，
真实视频精度不够。

本地 `server` 原型是另一套思路：用户框选篮网区域，对框内帧间差分得到运动能量曲线，
用局部稳健基线和尖峰形态判定「网动了」，再把事件剪成片段。本文件回答两个问题：

1. 这套方法能不能直接替换现有服务端识别？
2. 如果不能，哪些部分值得借鉴，应该放在哪个阶段？

## 2. 它是怎么判的

```text
上传视频 + 归一化篮网 ROI
  → 按 12 FPS 抽帧，缩到 960 宽
  → ROI 灰度 + 高斯模糊 + 帧间 absdiff
  → 每帧运动能量 = 差分均值
  → 局部中位数 + k·MAD 阈值（k：high=2.5 / normal=3.5 / low=5.0）
  → 连续超阈值 ≥3 帧 → 候选峰
  → 形态过滤：峰值/前 3 秒基线 ≥2、上升 ≤1.5s、绝对能量下限、片尾保护
  → 2.5s 冷却合并
  → 事件（start/end/peak/confidence）→ 剪辑
```

关键参数：`COOLDOWN_SECONDS=2.5`、`BASELINE_WINDOW_SECONDS=3.0`、
`RATIO_MIN=2.0`、`RISE_MAX_SECONDS=1.5`、`MIN_ABS_ENERGY_FLOOR=0.5`、
`MIN_ABS_ENERGY_P90_FACTOR=0.35`。

它的输出语义是「**篮网发生了快速运动**」，默认把它当作进球；它不跟踪球、不判断
出手，也不区分命中/未中/盖帽/抢篮板/整理篮网。代码和文档里也明确写了这个限制。

## 3. 实测

### 3.1 素材

| 视频 | 时长 | 分辨率 | 内容/机位 |
| --- | ---: | --- | --- |
| 视频 1 | 7.3s | 1522×1080 | 手持横移扫过球场，篮网清楚但镜头在平移 |
| 视频 2 | 46.0s | 2326×1080 | 固定/半固定机位拍半场，篮网清楚，有球员在网前走动 |

两段都是 HDR HEVC 手机原片；本地另有一份转码 AVC 副本，时长一致。

### 3.2 方法

- 直接用原型的 `analyze()`，`analysis_fps=12`，`sensitivity=high`；
- 手工框选篮网 ROI，不改其它参数，不做调参；
- 对每个事件抽取前后帧，人工看是否真的穿网。

对比了三种 ROI 和两档灵敏度：

| ROI | 归一化 x,y,w,h | 说明 |
| --- | --- | --- |
| 宽 ROI | 0.542, 0.319, 0.060, 0.074 | 含筐沿、网和网下一小段 |
| 紧 ROI | 0.548, 0.328, 0.044, 0.048 | 只框网 |
| 更大 ROI | 0.528, 0.298, 0.088, 0.112 | 含更多筐架/背景 |

### 3.3 结果

**视频 1（手持横移，7.3s）**：只报 1 个事件（0.7s），逐帧看是穿 13 号球衣的球员从
网前走过，不是进球；之后镜头平移，固定 ROI 已对不上篮网，没有再报事件。**这段不可用。**

**视频 2（半固定机位，46.0s）**：

| 事件时刻 | 人工核对 | 说明 |
| ---: | --- | --- |
| 4.1s | 误报 | 球员从网前走过，身体占满 ROI |
| 14.4s | 进球 | 球从网上方入网 |
| 19.5s | 进球 | 同上 |
| 26.9s | 误报 | 球员头部进入 ROI 下缘 |
| 31.3s | 进球 | 球入网 |
| 35.8s | 进球 | 球入网 |
| 41.6s | 进球 | 球从右侧入网（宽 ROI 漏掉，紧 ROI 能报） |

- **宽 ROI + high**：6 个事件 = 4 个进球 + 2 个误报（4.1、26.9），漏 41.6；
- **紧 ROI + high**：6 个事件 = 5 个进球 + 1 个误报（4.1），恢复 41.6、去掉 26.9；
- **紧 ROI + normal**：5 个事件 = 4 个进球 + 1 个误报，漏 41.6；
- **更大 ROI + high**：8 个事件，额外多出 4.7s、8.0s、44.0s 等干扰/待定事件，仍漏 41.6。

所以在这段 46s 视频上，**紧 ROI + high 能得到 5 个进球 + 1 个人走过造成的误报**；
这个结果已经接近「能用来剪命中片段」，但还达不到产品级精度。视频末尾 44s 附近
还有一次球到筐/网的动作，是否进球需要标注确认，本文不计入。

局限：单段视频、手工 ROI、人工目测标签、没有调参，不能当作正式评测结果；它的意义
是暴露失败模式，而不是给出准确率承诺。

### 3.4 失败模式

1. **ROI 里任何人/物的运动都会触发**：球员走过、头进入画面、镜头抖动，都会被当成
   「网动」。这是 4.1s 和 26.9s 误报的原因；紧 ROI 能去掉一部分，但人去挡网时无法避免。
2. **镜头必须固定**：视频 1 横移时固定 ROI 很快失效；手持/抖动会同时引入全局运动。
3. **篮网要足够大、足够清楚**：远景里篮网只占画面宽度的 2–4%，缩到 640 宽分析时
   只剩十几像素，弱进球（擦网很轻）容易低于绝对能量下限。
4. **只判「网动」，不判「球」**：无法区分进球、盖帽、抢篮板、整理篮网；也不报未中，
   因此不能支撑「命中/未中」和命中率统计。
5. **需要人工框网 ROI**：App 现在让用户框的是篮筐开口，不是篮网；直接复用得改交互
   或从筐 ROI 推导网 ROI。

## 4. 方案权衡

| 方案 | 能判什么 | 场景假设 | 数据/许可 | 成本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 当前经典 CV 基线 | 投篮事件 + made/miss | 橙色球/筐、机位基本固定 | 无模型 | 已上线，调参收益有限 | 保留为兜底 |
| 篮网能量法（本原型） | 只判「网动」≈ 命中 | 固定机位、篮网大而清楚 | 无模型、无许可风险 | 最低，代码已存在 | 只做固定机位可选项/命中确认，不替换 |
| 学习型球/筐检测 + 跟踪 + 穿筐 | 投篮事件 + made/miss | 光照/球色/背景更鲁棒 | 需标注/训练；选 Apache-2.0 模型 | 2–4 周 | **主线** |
| 学习型/经典找球 + 篮网能量确认 | 先找出手/球，再用网动确认命中 | 固定机位效果最好 | 同上 | 主线 + 1–2 天 | 可作为提高命中精度的手段 |
| 音频/姿态辅助 | 碰筐声、出手动作 | 户外噪声、遮挡 | 少量数据 | 1–2 天 | 后续增强，不做主线 |

**推荐组合**：以学习型球/筐检测 + 跟踪 + 穿筐为主线（见 PR #13 的分阶段计划），
经典基线做兜底；篮网能量法作为「固定机位 + 网清楚」场景的可选命中确认/片段触发器，
不作为通用检测器，也不进主链路的关键路径。

## 5. 值得借鉴的部分

不是「整个 server 都不能用」，而是「它的检测信号不能当通用识别，后处理可以复用」：

1. **ROI 时序能量 + 局部中位数/MAD 基线**：比全局固定阈值稳，能适应不同视频的能量水平；
2. **尖峰形态过滤**（快速上升、峰值/基线倍率、连续帧、片尾保护）：能压掉缓慢晃动；
3. **冷却合并 + 置信度打分**：和现有 `shot_geometry` 的去重思路一致，可复用到片段后处理；
4. **手工 ROI 的产品路径**：App 已有手动圈筐，扩展成「圈网」或「圈筐+网」的交互成本不高；
5. **纯 CPU、无模型、无许可风险**：适合作为固定机位模式的最低成本方案。

建议的落地方式（按优先级）：

- **P0（不改主链路）**：把这段逻辑当作评估/标注工具——用它先跑候选片段，人工确认后
  作为评估集标签，能低成本积累真实数据；
- **P1（可选后端）**：新增 `BASKETBALL_DETECTOR=netmotion`，输出 `made=True` 的事件；
  要求用户框紧篮网 ROI，并加一个「事件前几秒内 ROI 上方出现过球」的门控（可用现有
  橙色球候选或轻量球检测器），压掉人走过的误报；
- **P2（混合精度）**：主线检测器找到「出手/穿筐候选」后，只在候选前后 2–3 秒窗口跑
  篮网能量，作为 made 的二次确认；这比整段跑更便宜，也能减少纯几何的擦筐/筐前穿过后误判。

## 6. 下一步

1. 给这两段视频补 `made/miss + 穿筐时刻` 标注，作为第一批评测样本；
2. 用同一套指标（事件精确率/召回率、命中精确率/召回率、时间误差）跑
   `classical` vs `netmotion(紧 ROI)` 的 A/B；
3. 若固定机位样本上 `netmotion` 的命中精确率能达到目标（建议 ≥95%），再做 P1；
   否则只保留 P0/P2 的后处理思路；
4. 需要更多「固定机位、篮网清楚、有人从网前走过」的样本，才能判断人走过误报能否
   用球门控压住；这两段里视频 1 是手持横移，不适合评估该方案。
